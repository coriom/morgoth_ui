# Desktop D2 read contract and authority

The candidate path is React WebView → eleven fixed Tauri commands → Rust `ManagementClient` → one owned loopback Management child → optional `/desktop-read/v1` GET routes → owned Unix-socket `morgoth_test`. React receives no API port, token, database address, SQL, filesystem path or dynamic URL. The native client disables proxies and redirects, limits connect to 2 seconds, total HTTP to 8 seconds and responses to 64 KiB, sends the private Management token, and accepts JSON only. The child authenticates Host, no Origin and one token before routing. Only the main Tauri window has permission to invoke the read commands.

The optional routes exist only if the launcher is passed `--test-pg-socket` by a D2 native process with `MORGOTH_DESKTOP_TEST_PG_SOCKET`. The backend refuses a non-owner-private socket directory, connects as the local OS user to the fixed database `morgoth_test`, checks the database name and uses a read-only transaction. A missing socket, Project, schema or table produces unavailable/404, never a fabricated empty result. The legacy default Project is refused. Project manifests are validated by Management; SQL uses only their validated schema identity and an additional `project_id` predicate. IDs from another Project return 404 on detail reads. Limits are 1–10 rows, offset 0–1000, deterministic order. The native client independently checks Project identity, source class, array bounds and historical marker. React validates again and keys caches by Project ID.

Project IPC is sanitized: `id`, `name`, `domain`, `legacy`, `configuration_valid`, `runtime_checked`. `manifest_path`, `workspace_root`, `vault_dir`, `runtime_dir`, `postgres_schema` and `chroma_prefix` remain native-only. Mission IPC contains bounded objective, state, revision, historical stages, gaps, failure codes, resume flag, row timestamps and **count** of committed receipts. Capability IPC contains ID/version/digest, state, validation state, safe source identity and a fixture-only approval marker. Raw JSONB, receipt results, grant rows, approval provenance, user IDs and internal model content are not projected. Unknown/malformed stored records fail closed.

`PENDING_APPROVAL` is a stored capability state, not a counted human approval request. `TEST_FIXTURE_ONLY` is not a grant. D2 has no grant, approve, execute, resume, retry, model-inference or research-start IPC command. The optional test read contract is not a production data authority. A future production read service requires its own review of identity, database access, retention, audit and approval provenance; simply pointing this socket adapter at another database is not supported.
